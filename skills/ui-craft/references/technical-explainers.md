# 技术讲解页

目标不是把文档做成海报，而是让读者形成可核验的心智模型。

## 内容顺序

1. **一句话问题**：用读者语言说明本页解释什么，不先讲实现名词。
2. **具体场景**：谁发起什么操作，输入和前提是什么。
3. **全景图**：只画主路径上的角色与状态，标出阅读方向。
4. **分步机制**：每一步同时给“发生什么、为什么、能观察到什么”。
5. **代码锚点**：只展示与当前步骤直接相关的代码，标出文件与行为，不贴整文件。
6. **对照与反例**：并列易混淆场景、正确/错误路径或修改前/后。
7. **边界与下一步**：说明不适用条件、未验证内容和读者可执行动作。

事实、推断、假设示例和风险示例要明确区分。讲解动画表达的关系必须先在文字中成立。

## 推荐布局

### 桌面

- 紧凑页头：标题、读者所需背景、主要操作，不用空泛营销口号。
- 主区优先采用“步骤导航 + 当前解释 + 主图/代码”的稳定结构。
- 步骤导航保持位置稳定；切换时不让读者重新寻找阅读位置。
- 代码列设置独立滚动或限制高度，但不能截断当前讲解所需上下文。
- 图注写结论，不写“图 1 展示了流程图”这类重复信息。

### 手机

- 把多栏改为有顺序的单栏，不用横向缩小整个桌面画布。
- 步骤导航可横向滚动，但当前项必须可见，并提供上一步/下一步按钮。
- 代码保留横向滚动与等宽字体；正文允许自然换行，长标识符使用 `overflow-wrap`。
- 固定底栏不能遮住焦点、代码或播放控件，考虑 safe area。

## 图解与动画

只有以下情况使用动画：

- 显示严格的先后顺序；
- 显示状态从 A 到 B 的转换；
- 显示请求、数据或控制权在角色之间移动；
- 对比两条路径在同一事件下的差异。

提供播放/暂停、上一步、下一步和重置；支持方向键，当前步骤用 `aria-current` 或等效状态表达。静止状态必须仍能读完整内容；减少动态效果时直接切换状态，保留颜色/文字反馈。

不要把每个卡片都做成可点击。只有能改变解释视角或显示更多证据的区域才交互。

## 代码呈现

- 等宽字体只用于代码、标识符和真正的数据，不用于所有小标签。
- 行号只在需要引用具体行时显示；高亮行必须被正文引用。
- 避免语法高亮颜色过多；关键字、字符串、注释之外，优先保持墨色。
- 复制按钮有成功/失败反馈，不遮挡最后一行代码。
- 示例使用真实或明确标注的简化代码，不把伪代码写得像可直接运行。

## 完成标准

读者不看源码也应能回答：触发者是谁、经过哪些状态、在哪里可能失败、如何观察、下一步是什么。随机选一处图或代码，正文应能解释它为何存在；否则删除。
