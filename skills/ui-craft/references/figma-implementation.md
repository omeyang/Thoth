# Figma 设计实现

仅在用户提供 Figma 设计、节点截图或可访问的设计上下文时使用。目标是按设计意图实现并融入现有工程，不是把 MCP 返回的示例代码原样贴进项目。

## 前置与降级

优先取得具体 frame/component 的 URL 或节点选择、设计上下文和截图。复杂设计先看节点结构，再按需读取子节点，避免一次响应截断后凭空补全。

- 有 Figma MCP：使用宿主已有工具读取设计上下文、节点结构与截图，不自行配置新服务或索取密钥。
- 只有截图/导出规范：明确可实现范围，无法确认的交互、约束和 token 标为待确认。
- 没有任何可视证据：不要声称“1:1 还原”；先按普通 UI 设计流程建立方向。

## 实施顺序

1. **定位目标**：确认文件、节点、目标页面/组件和要实现的视口。
2. **读取结构与画面**：同时保留设计数据与视觉参考；只看其中一种容易漏掉约束或实际效果。
3. **盘点工程**：读取现有 tokens、组件库、路由、状态管理、资源与测试约定。
4. **建立映射**：把 Figma 颜色、字体、间距和组件变体映射到项目角色；列出不匹配项。
5. **复用后扩展**：已有组件优先复用或扩展，不重复造按钮、输入框和浮层。
6. **使用真实资产**：采用设计提供的图片、图标和字体来源，保留授权边界；有真实资产时不用占位图替代。
7. **分阶段校准**：先结构和大尺寸，再字体、颜色、间距、资产，最后交互状态与响应式。
8. **截图对照**：在目标视口将实现与设计截图并排检查，修复后重新截图。

## 还原与工程冲突

Figma 输出是设计表达，不是最终代码风格。保留项目框架、语义 tokens、组件命名和数据流，不因为生成示例使用 React/Tailwind 就改写项目栈。

可访问性、平台行为或工程约束需要偏离设计稿时，记录位置、原因和视觉影响；涉及品牌或核心设计意图的偏离交由用户/设计确认。不要默默把设计稿中的错误变成更难用的“像素一致”。

## 验收清单

- 布局：对齐、尺寸、约束、滚动与目标视口一致；
- 字体：家族、字重、字号、行高、字距和自然换行；
- 色彩与资产：语义角色、图像裁切、图标风格、加载失败回退；
- 组件：变体、默认/悬停/按下/焦点/禁用及适用业务状态；
- 响应式：按设计约束重排，不把桌面稿直接缩小；
- 工程：复用现有组件，无平行主题，无无依据硬编码；
- 证据：目标视口截图和交互走查；未取得的节点或状态明确列为未验证。

评审输出把“已对照设计验证”和“主观看起来接近”分开。没有实际截图对照时，不宣称像素级或 1:1 一致。
