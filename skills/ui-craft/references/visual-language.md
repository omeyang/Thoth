# 视觉语言

## 层级与构图

先确定读者在 3 秒内要看到的对象，再安排尺寸和位置。层级优先来自内容顺序、尺度、留白和对齐，不依赖层层卡片。

- 工具/资料库：导航压缩为一条，首屏显示真实工作区或第一排内容。
- 讲解页：标题紧凑，核心图解与第一步解释进入首屏。
- 说服页：可以使用大型开场，但必须有一个与主题不可交换的主角。
- 让内容边缘形成明确对齐线；非对称布局也要有稳定的重复结构。
- 用密度表达用途：阅读区宽松，操作区紧凑，数据区对齐。

## 色彩

定义语义角色，而不是“主色 + 一堆相近色”：

| 角色 | 用途 |
| --- | --- |
| `background` | 页面底色 |
| `surface` | 与底色有实际层级需要的区域 |
| `foreground` | 主文字与关键图形 |
| `muted` | 次要信息，仍需满足可读性 |
| `accent` | 当前状态、主操作或一个视觉焦点 |
| `border` / `focus` | 结构边界 / 键盘焦点，二者不互相替代 |

高亮色越少越有效。避免灰色文字放在彩色底上导致对比不足；不能仅靠颜色表达成功、错误或当前步骤。浅色页不等于米色页，深色页不等于霓虹渐变页。

## 中文排版

- 使用可靠的系统字体回退；需要嵌入字体时确认授权、子集和加载成本，不把系统字体文件提取出来分发。
- 中文正文通常需要比英文更充足的行高；从 1.6–1.8 起按字体和栏宽调整。
- 标题避免过宽字距；正文不使用全大写式的中文标签替代信息层级。
- 中英文之间按项目排版规范保持一致；数字与单位不要意外换行。
- 不给中文强行合成斜体。强调可改用字重、颜色、下划线或版式。
- 标题使用 `text-wrap: balance` 作为渐进增强，同时确保自然换行也成立。
- 正文避免两端对齐造成过大字间空洞；长 URL、哈希和代码标识符允许安全换行。
- 字体个性来自明确的角色和尺度，不是加载很多字体。通常 1–2 个家族足够。

## 间距与形状

选择一小组间距并重复使用，例如 4、8、12、16、24、40、64 px；根据内容密度调整，不机械套用到所有端。

- 相关元素靠近，比给所有元素加边框更先表达分组。
- 圆角来自控件类型和整体语言；不要让标签、输入框、卡片和按钮全部同半径。
- 阴影只在表达浮层或可拖拽层级时使用；普通内容优先平面与边界。
- 细线应表示分隔、连接、顺序或坐标，不作为无意义装饰。

## 图像与图标

优先真实产品画面、主题相关照片或可解释机制的自定义图解。素材需要与内容分辨率匹配，首屏关键图设置尺寸以避免布局偏移。

使用同一套 SVG 图标风格；图标按钮必须有可访问名称。不要用 emoji 代替整套界面图标，也不要用装饰图片冒充真实案例。

## 减法检查

逐一问：这个徽章、眉题、渐变、边框、编号或动画删除了会损失什么信息？若答案只是“看起来更丰富”，优先删除。
