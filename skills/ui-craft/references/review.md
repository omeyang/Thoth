# 评审清单

分开回答“是否好看”“是否易懂”“是否可用”，不要用单一分数掩盖阻断问题。

## 优先级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| P0 | 无法完成主要任务或内容错误 | 主操作无效、手机遮挡、虚构事实 |
| P1 | 严重理解/可用性障碍 | 层级错乱、焦点不可见、关键对比不足 |
| P2 | 明显粗糙或方向不一致 | 模板感、风格漂移、重复装饰 |
| P3 | 可选 polish | 微小节奏、非关键动效 |

每条发现写 `位置 → 观察到的问题 → 影响 → 具体修复`。没有截图、代码或操作证据时标为推测，不写成已复现问题。

## 三个质量维度

| 维度 | 核心问题 | 典型风险 |
| --- | --- | --- |
| 顺畅地理解到行动 | 用户能否发现主要任务、理解下一步并完成与恢复？ | 主操作被埋没、多个同级 CTA、死路、过多不必要步骤 |
| 工艺与一致性 | 构图、字体、tokens、组件状态和响应式是否精确且符合方向？ | 硬编码漂移、模板感、缺少状态、画面与规范不一致 |
| 可信与可恢复 | 内容来源、AI/自动化结果、错误与后果是否诚实可理解？ | 虚构证据、静默失败、无修复建议、破坏性操作不可恢复 |

“步骤越少越好”只是诊断线索，不是固定上限。安全确认、必要输入和清晰分步比机械压缩点击数更重要。AI 生成内容需要按风险与产品约定表达来源、不确定性或复核需求，不在所有普通界面上无差别堆免责声明。

## 画面评审

- 首屏是否立即回答“这里是什么、我能做什么”？
- 视线是否先落在主角，而不是通知、徽章或装饰？
- 缩小或眯眼看时，明暗块是否仍有明确层级？
- 标题、正文、辅助文字和代码是否各自稳定？
- 是否有一个记忆点，而不是每个区域都争抢注意力？
- 手机是重新组织内容，还是桌面的缩小版？
- 主要操作是否清晰，次要操作是否被合理收纳？
- 错误是否说明发生了什么、如何修复，并保留用户已输入的内容？

## 任务走查

从真实页面推断主要任务，不看实现说明，走一条完整路径。记录每个动作前后可见状态、键盘结果和恢复路径。至少覆盖一次非理想输入或错误恢复。

## 交付记录

```text
方向：<一句话设计契约>
已验证：<视口、交互、键盘、减少动态效果、控制台/资源>
静态审计：<命令与结果>
未验证：<明确项目；无则省略>
剩余问题：<按 P0–P3 排序；无则省略>
```

不声称通过 WCAG 合规认证，除非完成相应完整评估。自动化脚本零发现也不等于无问题。
