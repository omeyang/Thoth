# 理解机制：按卡点选择，不按模板堆叠

## 费曼稿（必选）

先写不超过 100 字的无术语版本：

```text
一句话：______
谁：______
在什么前提下：______
发生什么：______
为什么会这样：______
结果是什么：______
如果不这样，会怎样：______
```

交给用户确认。讲不下去的位置就是证据或机制缺口，不能靠加图掩盖。必须使用的术语在首次出现处用普通语言解释；一段只表达一个结论，优先短句和主动语态。

## 机制选择

| 读者卡点 | 使用机制 | 验收 |
| --- | --- | --- |
| 抽象概念没有挂靠点 | 具体先行：先给一个真实或标明假设的实例 | 能复述角色、事件、结果 |
| 只记住结论，不理解过程 | 场景重现 + 时序展开 | 至少 3 步，每步有状态变化和“因为…所以…” |
| 正确与错误看起来差不多 | 近误对比 | 初始条件相同，只差一个变量 |
| 不知道为什么不选另一条路 | 自我解释 | 有问有答，答案能引用证据 |
| 类比被当成事实 | 类比 + 失效边界 | 明说类比在哪里不成立 |
| 图和文字各说各话 | 双重编码 | 图能一句复述，图注不新增事实 |
| 一屏信息过多 | 分块与信号 | 每屏约 3±1 块，加粗只给结论 |
| 读完不会决定 | 决策前置 | 首屏能看到选项、代价和可逆性 |

机制至少选两个，但必须对应当前真实卡点。两个只差一个变量的例子胜过五个各说各话的例子。

## 动画只讲变化

仅用于状态转换、因果链、时序、单变量对比。默认不自动播放；可暂停、单步、重置，最终状态静态可达。每个 step 有 `data-step`、状态变化和解释因果的 caption；同一份 `steps` 数据同时驱动画面、caption 与测试。支持 `prefers-reduced-motion`，只动画 `transform`/`opacity`，不引入重型动画框架。

换掉关键变量后画面仍一样，说明动画只是装饰，删除。没有动画的静态页面不需要播放器。

## teach-back（必选）

出 3–5 题，正式盲测固定覆盖概念、对比、反例、决策、边界五类。每题记录参考答案与常见误解。读者不看源码，只读页面作答；≥ 4/5 才通过。让读者说出“最不确定的一点”，不能用模糊语言掩盖证据缺口。

## 自洽检查

场景前提、角色和数值前后一致；原因与结果不倒置；对比只变一个变量；图、文、动画表达同一状态；建议都有适配边界；任何一段都不能只有作者凭内部知识才能看懂。
