# 阶段 2 — 代码采集 (collect-code)

## 目标

拉取与需求关联的**所有**真实代码变更，作为反讲的**事实侧**输入源 B。
跨仓库 / 跨模块是常态，不能遗漏。

## 输入

- 需求 ID
- （可选）关联 MR / PR / commit 列表（若需求单未关联）

## 步骤

1. **从需求单反查关联变更**
   - 阶段 1 产物中通常带有关联 MR / PR 链接或 commit hash
   - 若无，向用户询问关联的仓库和分支 / MR 列表

2. **采集 diff**（执行适配器 `code.md` 槽位）
   - 逐个仓库 / 模块拉取：
     - 变更元信息（标题、描述、reviewer、状态）
     - 完整 diff（含新增文件全文，不只是 hunk）
     - commit 列表与每条 commit message

3. **归档结构**

   ```
   .reqloop/code-{id}/
   ├── INDEX.md              # 仓库(模块) × 变更列表总览
   ├── repo-a/
   │   ├── mr-123.diff
   │   ├── mr-123.meta.md
   │   └── commits.md
   └── repo-b/
       └── ...
   ```

   单仓库场景下顶层目录按模块拆（见 `adapters/lite/code.md`）。

4. **INDEX.md 必含字段**
   - 仓库（模块）名 / 变更标识 / 标题 / 状态 / 变更行数 / 关联需求 ID
   - 便于阶段 3 反讲时统一引用

## 取舍

- **只拉增量 diff，不拉全仓库**（阶段 4 由 code-review-graph 补全局视角）
- **新增文件例外**：新增文件必须拉全文，否则 review 时上下文不足
- **不跨需求采集**：即使一次变更里混入了其它需求，也按该变更整体归档，阶段 3 反讲时标注

## 失败处理

- 仓库访问失败 → 记录到 `INDEX.md` 并中止（缺代码不能反讲）
- 变更未合入 → 警告但继续（按当前 diff 处理，在 backspec 中标注状态）
