# 图表 PNG 导出与预览

这是用户在**所有项目**中的图表交付偏好，不限于某个仓库、文档站或业务。面向用户交付新增、修改或指定导出的图表时，默认同时提供独立 PNG，方便完整查看、下载和迁移。用户当次指定只要源码、其他格式或外观时，以当次要求为准。

## 默认结果

- PNG，白色不透明背景，浅色主题。只有用户另有要求时才附加 SVG。
- 按完整图表画布以 **4 倍分辨率直接渲染**，不把低分辨率截图放大。
- 保留原图内容、步骤、参与方、连线方向与布局。可以改善导出副本的文字对比度、标题框留白和画布边界。
- 按图表自身尺寸导出，避免被网页列宽、横向滚动容器或原 SVG 的 `viewBox` 裁切。
- 先在本机生成并逐张检查，再交付每张图片的名称和可打开的预览链接。用户自行确认和同步到 WIKI；本技能不包含 WIKI 写入。
- 保留原图和可重新生成的源码。单纯导出图片不替换正文中的原图，也不更改业务事实。

## 找全来源

先查看实际项目的源稿、构建方式、样式和已有图表工具，不假定存在 `src/`、`content/` 或某个构建脚本。

| 来源 | 处理方式 |
|---|---|
| Mermaid 代码块 | 优先复用与当前源稿一致的已渲染 SVG；缓存缺失时使用项目现有 Mermaid 渲染方式。本机 pretty-mermaid 可在适合时使用 |
| 手工内联 SVG | 提取完整 SVG，保留它自己的样式、`defs`、marker 和其他内部引用 |
| 已有独立 SVG | 检查是否依赖外部 CSS、字体或资源，再选择浏览器或 SVG 渲染工具 |
| 已有 PNG 等位图 | 优先交付清晰的原文件；像素不足时从矢量或图表源码重新生成 |

批量导出时，按页面顺序核对全部图及所属标题；不要只数 Mermaid 代码块，也不要用缓存目录的文件数代替当前页面图数。

## 渲染完整 PNG

优先复用项目可用的渲染工具。浏览器渲染可以用 Puppeteer 或 Playwright 配合无头 Chromium；先确认已有依赖、浏览器和字体的位置，不写死 Node.js 版本目录。

1. 在任务专用临时目录准备导出数据。每张 SVG 单独渲染，防止不同图的 CSS 类、变量和 marker ID 相互影响。
2. 加载该图实际依赖的项目样式和本地字体，固定为浅色主题。字体可内嵌为 data URL 或从本机服务加载，中文字体需要覆盖图中的字符。不要依赖外链字体。
3. 将页面设为白底、零页边距，取消 SVG 和容器的响应式宽度限制；保留图内样式与箭头定义。
4. 在图和字体插入页面后等待 `document.fonts.ready`，再用 `getBBox()` 测量可见文字与图形，跳过 `defs` 中的定义。
5. 将可见内容边界与原 `viewBox` 取并集，必要时扩大画布，并在扩展的一侧留出约 16 个逻辑像素。尤其检查最右侧的自调用说明和底部注释。边界测量未必包含完整描边、箭头或阴影，仍需实际预览。
6. 标题文字紧贴边框时增加框内留白；说明文字过浅时加深颜色。只调整导出副本。
7. 将 SVG 的 `viewBox`、显示宽高和浏览器 viewport 设置为完整画布，以 4 倍倍率生成 PNG。需要整数尺寸时向上取整。可以另外生成 1 倍小图用于检查。

Puppeteer 导出关键步骤示例；需先完成图表提取、样式加载和画布计算：

```js
await page.evaluate(() => document.fonts.ready);
await page.setViewport({
  width: Math.ceil(canvasWidth),
  height: Math.ceil(canvasHeight),
  deviceScaleFactor: 4,
});
await page.screenshot({
  path: outputPng,
  captureBeyondViewport: true,
  omitBackground: false,
});
```

页面此时只包含当前图，背景和尺寸已经设置正确。`captureBeyondViewport` 不会修复 SVG 自身的 `viewBox` 裁切。

对于样式完整、字体可用的独立 SVG，也可以使用 `rsvg-convert --zoom 4 --background-color white`。只有需要独立 SVG 附件时，才考虑额外把文字转为矢量轮廓，以消除字体依赖；PNG 不需要增加这一道处理。

## 检查与交付

逐张实际打开生成的 PNG，确认图的数量、文字、参与方和消息完整；中文没有缺字或方框，标签不重叠，连线和箭头没有被裁切；白底与实际像素尺寸符合要求。自动边界检查辅助定位问题，不能替代视觉检查。

图片放在项目惯用的附件或导出目录，以页面顺序和有含义的名称命名。若有生成式站点，遵循它的源文件与构建产物关系，避免手工维护两份。

预览沿用该内容已有授权范围内的站点或附件机制；有现成 Caddy 时可以给直接图片链接，没有时交付本地文件链接。不要为了导出图片自行把其他项目的内容发布到新站点，也不假定每个项目都使用相同域名、目录或权限。

本机 vault 文档站的具体目录、构建和 Caddy 规则见 [references/vault-preview.md](references/vault-preview.md)，只在处理这个站点时读取。

交付回复逐图列出名称和 PNG 链接，简述分辨率与检查结果，让用户可以直接打开或下载。

## 迁移完成后的清理

用户确认附件不再需要后，删除本次导出图、相应生成副本及任务专用临时文件；先核对目录内容，只删除空目录。保留 Markdown、Mermaid、手工 SVG 等原图源码及项目需要的渲染缓存。生成式站点按自身构建流程清理旧产物，并检查原文和其他资源仍然正常。

这份全局技能继续保留，后续项目从各自源码重新生成图片。
